# SOTF release readiness audit — 2026-10-05

## Decision and scope

**SOTF is not yet qualified for a macOS/Linux release.** The local sibling dependency layout works for the nine principal workspaces, but the tenth Cargo scope has a stale lockfile. Dependency consolidation, formatting, current-snapshot compilation and behavioral QA, native formats, systemwide packaging, and installed-product acceptance remain incomplete or unproven.

The immediate target is macOS and Linux. Windows, Android, and iOS are subsequent releases, with their own acceptance gates. Their absence must not be presented as completed support, but native Windows/mobile acceptance need not delay the first explicitly scoped macOS/Linux release. Shared-code defects affecting macOS/Linux still belong in the first release.

This report follows the current instruction: work locally, keep the existing branches, commit locally, and defer GitHub synchronization. Historical instructions in [yesterday's release plan](docs/release-plan-20261004.txt) to execute only on Gitea, push, or create review branches are superseded for this work. Historical technical requirements remain useful evidence and are identified below.

This is an audit and a release work list, not a claim that the listed repairs or full release tests have been performed. No product build, driver installation, signing, notarization, deployment, remote workflow, or publication was performed for this report. Existing source edits were preserved.

## 1. Local orchestration and reproducibility

The [root Justfile](Justfile) routes `dependencies`, `check`, `test`, `qa`, and `qa-release` through `_ci_only`, which exits 2 and tells the operator to dispatch Gitea Actions. The `local-*` aggregates list only six workspaces: they omit `sotf-daw`, `sotf-capture`, `sotf-systemwide`, and the independent AutoEQ GUI-demo scope. They are useful developer shortcuts but cannot qualify this release.

The [aggregate QA runner](scripts/release/qa.py) is directly invocable and already covers the nine roots and AutoEQ demo. It has before/after source/lock guards and command-level evidence. Its `check` phase checks ordinary workspace targets, with the demo explicitly all-feature; do not mistake that phase for all-feature qualification of every root. It explicitly labels a single-platform run as incomplete release coverage. It also permits named rejected upmixer experiment classifications and a narrowly defined Linux external-plugin sandbox coverage omission; inspect those inventories and cover the missing real runtime behavior separately.

**Required local changes:** expose the existing runners through local root recipes or a local command sequence; include all ten scopes; define local evidence locations outside tracked source; use `--locked` consistently; retain failures and process cleanup instead of timing out and relaunching silently. Use local commits as source identity. No branch, remote merge, or GitHub operation is needed to do this.

Pin the compiler used for the release rather than relying on moving `stable`. Reconcile the old Docker compilers (1.90/1.95 in inspected ARM recipes), the math workspace's 1.92 pin, and the actual host compiler with the final supported MSRV/dependency requirements. This audit did not prove an MSRV violation; the mismatch is an unqualified build-environment difference. Reuse the MBX target/cache directories for speed, while recording the exact profile, target, compiler and features. Cache hits are not qualification evidence by themselves.

Local source dependencies are ready in the nine root graphs. External forks still use immutable Git references because their source trees are not present here: examples include wgpu, Zed utility crates, Tract, Librespot, nalgebra, CoreAudio, PSM and the optimizer fork. The successful offline metadata runs show this machine has enough cache to resolve them. They do not prove a clean Linux machine can build without GitHub access. If the release must build entirely disconnected, prepopulate and hash the external sources/registry archives for each builder, or vendor the required sources deliberately. Do not claim all Git dependencies were eliminated.
